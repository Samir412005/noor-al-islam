# 🛡️ حارس نور الإسلام (Noor Guardian)

خدمة **مستقلّة** تراقب بوت نور الإسلام، تكتشف الخلل، **تُصلحه تلقائياً**، وتُبلّغ المالك
عبر قنوات متعدّدة. ليست جزءاً من البوت الذي تحرسه: لها عملياتها وسجلّها وتنبيهاتها.

---

## الفكرة: من يراقب البوت؟

إذا سقط البوت، فلا يمكن للبوت نفسه أن يُبلّغك بأنه سقط. لذلك:

1. **الحارس يعمل منفصلاً** عن البوت الهدف (عملية أخرى، سجلّ آخر، إعدادات أخرى).
2. **تنبيهاته لا تعتمد كلّها على البوت** — في العطل الحرج يُنبَّه عبر التقويم أولاً.
3. **لا حلقة إصلاح لا تنتهي**: ميزانية إصلاح لكل فحص في الساعة + تهدئة بين التنبيهات.
4. **الحارس لا يرمي traceback** ولا يُسقط نفسه عند أي فشل (كل الفحوصات والإصلاحات محميّة).

### قنوات التنبيه الأربعة

| القناة | متى تُستعمل | تعتمد على البوت الهدف؟ |
|---|---|---|
| 🤖 **بوت الحارس** (`GUARDIAN_BOT_TOKEN`) | أول قناة دائماً (الأقوى): رسالة من بوت مستقلّ واجهته التفاعلية | لا |
| 📅 **تقويم Google** | العطل الحرج: إشعار على هاتف المالك | لا |
| ✈️ **البوت الهدف** (البوت نفسه) | عندما يكون البوت سليماً ويستطيع الإرسال | نعم |
| 📝 **مسودّة Gmail** | سجلّ مكتوب يبقى في بريد المالك (`GUARDIAN_NOTIFY_DRAFT`) | لا |

الترتيب: في **الخطر الحرج** تُجرَّب القنوات بالترتيب (بوت الحارس ← التقويم ← البوت ← المسودّة)،
وفي **التحذير** يُقدَّم البوت الهدف (الأسرع). تُرسل القناة الناجحة فقط، ويُسجَّل اسم ما نجح.

> ويُسجَّل في `guardian/state/incidents.jsonl`.

## التشغيل

| الأمر | ماذا يفعل | ما يُطبع |
|---|---|---|
| `bash scripts/run_guardian.sh` | **دورة مستمرة**: فحص ← إصلاح ← تنبيه كل دقيقة | رسائل البدء والتنبيهات |
| `python -m guardian.daemon` | نفس الدورة المستمرة مباشرةً | `🛡️ الحارس بدأ — كل N ثانية` |
| `python -m guardian.daemon --once` | **دورة واحدة** ثم خروج (مفيد مع cron) | تقرير الحالة، ورمز الخروج 1 عند وجود خلل |
| `python -m guardian.daemon --status` | تقرير الحالة الآن + آخر الحوادث | ✅/⚠️/🛑 لكل فحص |
| `python -m guardian.daemon --selftest` | يفحص الحارس نفسه وقنوات تنبيهه | نتيجة اختبار التقويم والبوت |
| `bash scripts/run_guardian_bot.sh` | **بوت الحارس التفاعلي** (polling، مستقلّ) | رسالة تشغيل، و`🛡️ بوت الحارس يعمل: @...` |

### بوت الحارس التفاعلي (أوامر تيليجرام)

`/start` (ترحيب + زرّ «🔍 افحص الآن») · `/status` (تقرير مفصّل) · `/checks` (جدول مختصر) ·
`/fix <الفحص>` (إصلاح محدّد، يقبل الأسماء العربية) · `/restart` (إعادة تشغيل كاملة) ·
`/logs [n]` (آخر السجلّات، 20 افتراضياً و60 أقصى) · `/incidents` (آخر 10 حوادث) ·
`/mute <دقائق>` و`/unmute` (كتم تنبيهات بوت الحارس وحده) · `/help`.

- **مشرفون فقط**: من `ADMIN_IDS` في `.env` وصاحب البوت في قاعدته؛ غيرهم يُردّ عليه بلطف ويُتجاهل.
- الكتم يُخزَّن في `guardian/state/bot_mute` (وقت انتهاء بسيط) ولا يمسّ إعدادات الحارس الأخرى.
- بدون توكن يطبع رسالة عربية توضّح الخطوة اليدوية ثم يخرج برمز 2 (بلا traceback).

### cron (بديل عن الدورة المستمرة)

```cron
*/5 * * * * cd /home/user/.workspace/noor-islam-bot && python -m guardian.daemon --once >> logs/guardian.log 2>&1
@reboot     cd /home/user/.workspace/noor-islam-bot && bash scripts/run_guardian.sh >> logs/guardian.log 2>&1
```

## ⚠️ خطوة يدوية واحدة لا يمكن لأي وكيل فعلها

إنشاء **بوت الحارس** عبر @BotFather ثم وضع توكنه في متغيّر البيئة:

1. افتح تيليجرام وابحث عن **@BotFather**.
2. أرسل `/newbot` واتّبع الخطوات حتى تحصل على التوكن (شكل `123456:AA...`).
3. ضعه في البيئة: `export GUARDIAN_BOT_TOKEN=...` (أو في `.env` بجانب المشروع).
4. شغّل: `bash scripts/run_guardian_bot.sh`.

**الحارس يعمل كاملاً بدون هذه الخطوة**: التنبيه يصل عبر **تقويم Google** و**البوت الهدف**
و(اختيارياً) مسودّة Gmail. بوت الحارس مجرّد قناة إضافية أقوى + واجهة تفاعلية.
(`GUARDIAN_BOT_TOKEN` لا يُطبع في أي سجلّ ولا رسالة.)

## التدريب (Drill)

يُحقن الحارس أعطالاً حقيقية ثم يقيس هل أصلحها فعلاً:

```bash
python scripts/guardian_drill.py            # كل الأعطال
python scripts/guardian_drill.py --fault webhook
```

**النتيجة الحقيقية المسجّلة: 4/4 أعطال أُصلحت تلقائياً**

| العطل المحقون | الإصلاح | النتيجة |
|---|---|---|
| قتل عملية خدمة | `restart_workers` | ✅ تعافى |
| قتل المشرف والحراسة | `restart_supervisor` + `restart_keepalive` | ✅ تعافى |
| إفراغ الويب هوك | `assert_webhook` | ✅ تعافى |
| فقدان ملف بيانات | `refetch_data` | ✅ تعافى |
